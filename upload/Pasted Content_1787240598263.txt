# PROMPT XÂY DỰNG / NÂNG CẤP HỆ THỐNG SMART EXCEL DATA ENTRY & PRODUCTION TRACKING

Bạn là Senior Full-Stack Developer, Software Architect và Business Analyst có kinh nghiệm xây dựng hệ thống quản lý dữ liệu sản xuất, gia công, Excel automation và production tracking.

Tôi đang có một hệ thống web dùng để:

* Import Excel.
* Đọc Master Data.
* Nhập dữ liệu sản xuất.
* Tự động lookup dữ liệu.
* Tự động điền các trường liên quan.
* Export dữ liệu ra Excel.

Tuy nhiên hệ thống hiện tại đang có nhiều lỗi và thiếu các nghiệp vụ quan trọng.

Hãy **nâng cấp hệ thống hiện tại**, KHÔNG được đơn giản hóa các chức năng đã có.

---

# 1. MỤC TIÊU HỆ THỐNG

Hệ thống phải trở thành một:

> Smart Excel Data Management + Production Order Tracking + Processing/Outsource Tracking System.

Hệ thống phải cho phép quản lý toàn bộ luồng:

```text
ORDER
   ↓
OUTPUT
   ↓
SPENDING / PROCESSING
   ↓
INPUT
   ↓
COMPLETED
```

Trong đó:

* `Order`: số lượng đặt hàng / số lượng cần đưa đi gia công.
* `Output`: số lượng thực tế xuất đi gia công cho công ty khác.
* `Spending`: số lượng đang trong quá trình gia công.
* `Input`: số lượng đã nhận về sau khi gia công.
* `Completed`: số lượng hoàn thiện cuối cùng.

Mục tiêu:

```text
Order = Output = Input
```

Nếu các số lượng không cân bằng, hệ thống phải tự động phát hiện và cảnh báo.

# 9. DEADLINE PRIORITY

Một Factory PO có thể xuất hiện nhiều lần.

Ví dụ:

```text
Factory PO: MH26110228

Deadline:
2026-08-25
2026-08-20
2026-08-18
```

Khi user nhập:

```text
MH26110228
```

hệ thống phải ưu tiên record có:

```text
Dead Line gần nhất
```

nhưng phải đảm bảo:

```text
Dead Line >= Current Date
```

Ví dụ hôm nay:

```text
2026-08-20
```

thì:

```text
2026-08-20 ← ưu tiên
2026-08-25
2026-08-30
```

Nếu tất cả deadline đã quá hạn:

```text
2026-08-10
2026-08-15
```

thì ưu tiên:

```text
deadline gần current date nhất
```

và phải đánh dấu:

```text
OVERDUE
```

# 23. BALANCE LOGIC

Tối thiểu:

```text
Order = expected quantity
Output = quantity sent to processing
Input = quantity received back
```

Tính:

```text
Processing = Output - Input
```

Nếu:

```text
Output > Input
```

thì:

```text
Processing > 0
```

Ví dụ:

```text
Output = 100
Input = 60

Processing = 40
```

# 87. YÊU CẦU CUỐI CÙNG CHO AI CODING AGENT

Trước khi code:

1. Phân tích codebase hiện tại.
2. Xác định các lỗi hiện tại.
3. Không xóa các chức năng đang hoạt động.
4. Xác định database schema hiện tại.
5. Xác định Excel import/export implementation hiện tại.
6. Xác định nguyên nhân lỗi Color Code 1/2.
7. Xác định nguyên nhân lỗi đảo thứ tự export.
8. Xác định nguyên nhân import Excel thất bại.
9. Đề xuất migration nếu schema cũ không phù hợp.
10. Sau đó mới tiến hành sửa code.

Khi sửa:

```text
DO NOT rewrite the entire application unnecessarily.
DO NOT hard-code specific Factory PO.
DO NOT hard-code MAFATE only.
DO NOT rely on Excel column index.
DO NOT silently overwrite data.
DO NOT lose original Excel values.
DO NOT randomly select a Master Data record.
```

Mọi logic quan trọng phải có:

```text
Validation
Error Handling
Logging
Unit Test
Integration Test
```

Cuối cùng cung cấp:

```text
1. Source code
2. Database schema
3. API documentation
4. Migration script
5. Test cases
6. README
7. Docker configuration
8. Sample Excel files
9. Sample Master Data
10. Sample Production Transactions
```

Hãy triển khai theo từng module và đảm bảo mỗi module hoạt động hoàn chỉnh trước khi chuyển sang module tiếp theo.
